## 1. Архитектура и технологии

```text
React / Three.js → Vite build:android → dist-android
                                          ↓ android:sync
Android app/src/main/assets/www → WebViewAssetLoader → системный WebView
                                                          ↕ мост сообщений
                                               Kotlin Activity / native SDK
                                                  ↙                  ↘
                                         Unity LevelPlay       Firebase Auth / API
                                                  ↓                  ↓
                                          S2S callback → backend → Firestore
```

Сайт игры не требует отдельного хостинга: JS, CSS, звуки и прочие игровые ресурсы находятся в APK. Интернет используется для рекламы, входа и синхронизации. Системный WebView не включается целиком в APK. Unity используется как поставщик рекламного SDK, движок игры остаётся Three.js.

| Реклама | Native Unity LevelPlay Android SDK; сначала одна сеть Unity Ads и один rewarded placement, без лишних адаптеров |

Firebase — рекомендация для следующего этапа, а не уже подключённый сервис. SDK авторизации/сохранений подключать на нативной стороне, не дублировать одновременно в WebView. Токены остаются в native-части; игре передаются результаты команд и данные профиля.

### Этап 5. Облачные сохранения и API

Предлагаемый путь: **Firebase Auth + Firestore**, затем **Cloud Functions** для авторитетных операций и рекламных callback. Spark не требует платёжного метода; Firestore Standard имеет бесплатные квоты: 1 GiB хранения, 50 000 чтений и 20 000 записей в день. Это не безлимитное бесплатное API. Для развёртывания Cloud Functions требуется **Blaze с подключённым биллингом**; бесплатные квоты не гарантируют нулевой счёт. Тарифы, регион и доступность повторно проверить перед подключением. [Тарифы Firebase](https://firebase.google.com/pricing), [условия Cloud Functions](https://firebase.google.com/docs/functions/get-started).

Если нужна только копия сохранения через игровой аккаунт Google, можно рассмотреть Google Play Games Saved Games вместо Firestore. Он не заменяет сервер проверки рекламы и журнал валюты. Параллельно два хранилища не внедряем; основной план ниже — Firebase. [Google Play Games: cloud save](https://developer.android.com/games/pgs/savedgames).

- [ ] **7.8** Одной транзакцией записать обработанный eventId и прибавить 2000. Повтор callback не даёт награду. Клиентский onAdRewarded запускает ожидание/обновление профиля, а не второе начисление поверх серверного.
- [ ] **7.9** Поздний callback после закрытия/убийства приложения обрабатывается сервером; клиент получает новую ревизию при следующем входе. При задержке показать «Подтверждаем награду», не выдавать валюту по таймауту.
- [ ] **7.10** Пропуск, ошибка и закрытие без подтверждения не начисляют монеты. При no-fill вернуть доступное меню. Возврат из рекламы не продолжает поставленный на паузу бой автоматически.
- [ ] **7.11** На тестовых объявлениях проверить успех, пропуск, no-fill, двойной тап, поздний/повторный callback, обрыв сети, поворот, перезапуск, смену аккаунта. Результат успешного события — ровно +2000 с сохранением.

**Готовность:** добровольный показ, подтверждение сервером, одно начисление на событие и восстановление результата из облака.

## 4. Команды для будущего исполнения

```powershell
# Из корня hpproject
npm.cmd run build:android
npm.cmd run android:sync -- "C:\Users\стас\AndroidStudioProjects\hpgame"

# Из Android-проекта, с настроенным JDK
Set-Location "C:\Users\стас\AndroidStudioProjects\hpgame"
.\gradlew.bat assembleDebug --console=plain
# Подключённый телефон с USB debugging:
.\gradlew.bat installDebug
# После настройки release-подписи:
.\gradlew.bat bundleRelease
```

Не копировать весь репозиторий в www. Не запускать старый prepare-android поверх будущих ручных изменений рекламы/облака без сверки: он изменяет нативные файлы.

## 5. Последовательность и отметки done

Сначала **1–4: самостоятельный локальный APK**, затем **5–6: аккаунт, профиль и мост**, после — **7: реклама за 2000 stones**, в конце **8: выпуск**. Базовую игру можно проверять и распространять до рекламы, выполнив относящиеся к ней проверки release.

Отметка выполнения: `done — дата — версия/коммит — устройство — результаты — известные ограничения`.

Могу редактировать файлы и выполнять Vite/Gradle/ADB-команды в доступной среде. Управление окнами Android Studio зависит от подключения к приложению. Действия с аккаунтами, платёжными данными и ключами оформляются при реальном выполнении, не во время подготовки этого плана.
