# UI 50 — адаптация меню и игровых экранов

23.11.2026, ветка `android-port-5.5.0`, версия разработки **5.6.0**, Android **5600**. Отдельный запрос пользователя разрешает этот UI после стабильной базы 5.5.0. Стабильная метка и баланс не менялись. Это отчёт о реализации и программных проверках, не акт приёмки на телефоне.

## Выполнено по запросу

1. Hyped Pot, версия и кошелёк закреплены в шапке. Главное меню без прокрутки: фактическая высота переведённых блоков измеряется ResizeObserver, не поместившиеся блоки переходят на следующую страницу. Внизу стрелки и номер страницы. В подразделах длинные описания/магазин продолжают прокручиваться в отдельной области.
2. Язык только в главном меню. Подготовка арены: верхняя кнопка возврата, скрытая по умолчанию помощь по ?, одна карточка зелья со стрелками. Выбранный набор отображается ниже, его кнопки возвращают к карточке. Выбор и качество хранятся независимо от текущего слайда; проверки запасов, 3/4 слотов и количества копий сохранены.
3. Вводный текст обучения показан отдельным шагом. «Следующее» открывает практику. В landscape поле справа, элементы слева; в portrait поле между информацией и кнопками. SVG всегда квадратный и внутри доступной области; внешней прокрутки нет. Только длинный текст info на крайне коротком экране допускает свой скролл. Распознавание, 2 повтора и разовая награда прежние.
4. В обоих режимах портрет на touch-устройстве блокирует ввод и ставит игру на штатную паузу. Надпись переведена на пять языков. Поворот не отменяет чужую паузу: для продолжения нажать ▶. Системную блокировку ориентации не включали, чтобы меню и уроки работали вертикально.
5. Температура и помешивание стоят рядом снизу по центру. SVG, проценты и волна букв сохранены.
6. Руны котла ниже на .25 мировой единицы; прозрачность плавно меняется циклом 6с, примерно 3с видно/3с скрыто. Reduced motion оставляет подсказки видимыми.
7. Распознанное заклинание без цели вызывает отдельную трёхсекундную надпись с волной букв. Выбранный котёл, ингредиент, враг, снаряд, монета, зелье или удерживаемый объект исключают лишнюю подсказку. Существующий обработчик каста продолжает работать.
8. Руны ингредиентов отодвинуты вниз ещё на .26 единицы, получили тот же цикл; не перехватывают касания. На коротком кадре их размер 36px.
9. Touch-камера варки ближе на 8% при штатном landscape aspect; предметы и коллизии не масштабируются. На кадре высотой <600 рецепт выводится Html 14px вместо маленьких 3D-глифов, данные и цвета прежние.
10. Общий GameFrame подбирает соотношение сторон, не растягивая сцену и не уменьшая весь DOM через transform. В настройках Auto / Компактный16:10 / Широкий16:9, выбор сохраняется отдельно. При первом запуске Auto без дополнительного диалога.
11. Тот же кадр применяется к арене, вместе с HUD и следом. Наклон камеры арены и геометрия стола прежние. Монетки наград ориентируются на реальный прямоугольник счётчика относительно Canvas, поэтому боковые поля не смещают цель.
12. При коротком экране уменьшены избыточные панели и размеры индикаторов, а мелкие подписи подняты: основной текст 14px, состояния врагов/кристалла 12px, руны котла с подписью 12px, значения22px. Развёрнутые подсказки занимают максимум30% ширины и55% высоты, доступны собственной прокруткой.

## Форматы и расчётные размеры

Числа ниже — CSS pixels, не физические пиксели матрицы телефона. Android density/WebView viewport влияют на соответствие физическому разрешению. Auto ограничивает ширину/высоту рамкой 1.5–1.8; 16:10 и16:9 фиксируют выбранное отношение. На необычных экранах добавляются симметричные поля. Пресет влияет на оба режима, меню остаётся во всю доступную область.

| Доступный viewport | Кадр Auto | Назначение проверки |
| --- | --- | --- |
| 568×320 | 568×320 | Небольшой старый телефон landscape |
| 640×360 | 640×360 | Обычный небольшой landscape |
| 844×390 | 702×390 | Вытянутый телефон, поля по71px |
| 1280×575 | 1035×575 | Формат приложенного телефонного снимка |
| 1024×768 | 1024×682.7 | Планшет4:3, поля сверху/снизу |
| 2560×1080 | 1944×1080 | Очень широкий экран |
| 320×568 | Игра скрыта экраном поворота | Меню/обучение доступны |

При ширине/высоте значительно меньше320 CSS px либо системном увеличении шрифта возможен недостаток места для длинного отдельного блока. Настройки формата не обещают исправить произвольный browser zoom. На стандартных проверенных расчётом размерах все мировые точки ингредиентов и котёл остаются в кадре. Окончательное совпадение с эталоном требует реального рендера на устройстве.

## Проверки

- 276 тестов `node --test --test-reporter=dot tests/*.test.mjs` прошли: включая прежние механики, инвентарь/качество, обучение, жесты/touch; пять новых проверок кадра/проекций/пагинации/переводов.
- ESLint затронутых JS/JSX прошёл.
- Веб-сборка Vite прошла. Android Vite + Gradle assembleDebug прошли, внешний проект hpgame обновлён; сведения об APK в mobile/PORT_STATUS.md.
- Компьютерная визуальная проверка не состоялась: CUA вернул `native pipe unavailable` и `browser access host unavailable`. Скриншоты после изменений и тесты реального touch не получены. Не выдавать программные проверки за телефонную приёмку.
- Существующее предупреждение Vite о большом JS-chunk остаётся; тяжёлых моделей/текстур и зависимостей не добавлено.

## Ручная приёмка следующего запуска

- [ ] Установить 5.6.0 поверх прежней версии без очистки профиля. Проверить покупки, язык, зелья и достижения.
- [ ] Меню320×568 и568×320: пройти все страницы, сменить язык на каждый из5, выбрать миссию; заголовок и стрелки не уходят за край.
- [ ] Пикер: выбрать3/4 зелья разных качеств, пролистать туда/обратно, сверить набор и начать бой.
- [ ] Обучение portrait/landscape: вступление → практика, провести все типы жестов, повернуть во время рисования, проверить совпадение линии и пальца.
- [ ] Варка: клик по котлу/всем ингредиентам/левому врагу, касты и перенос пальцем; рецепт читается, руны не мешают выбору, индикаторы рядом.
- [ ] Повернуть активную варку в портрет: таймер, температура, враги не идут; после поворота нажать ▶, перенос и распознавание работают.
- [ ] Повторить на арене, включая снаряд, перенос куба, бросок зелья, монету и полёт наград.
- [ ] На обоих режимах проверить Auto/16:10/16:9, повторный запуск сохраняет выбор. Сравнить с эталонами при скрытой ? панели.
- [ ] Проверить отсутствие UI/console ошибок, офлайн-запуск, фон/возврат на Android10 с актуальным WebView. Для прежнего дефекта пустого экрана всё ещё нужны модель, WebView и logcat.
